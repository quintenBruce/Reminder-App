# Remind: Firebase, Google Cloud, and GitHub setup

This guide deploys the TypeScript PWA, Firestore rules, and Cloud Functions from GitHub to Firebase project `reminder-app-a2150`. Any verified Google account can sign in; each account has a private reminder list and conversation history. One successful deployment is enough to start using the app.

## 1. What to copy, and where it goes

Use the Firebase project **`reminder-app-a2150`** in every Firebase and Google Cloud screen below. The GitHub repository is [quintenBruce/Reminder-App](https://github.com/quintenBruce/Reminder-App), and its deployment branch is **`master`**. Your Firebase Web SDK config is already in [cloudbuild.yaml](../cloudbuild.yaml) and [web/.env.example](../web/.env.example); do **not** paste the whole `initializeApp(...)` snippet into either file or into a Cloud Build field. `storageBucket` and `measurementId` are unused.

Three values still need to be entered. Complete the relevant row **before** the first Cloud Build trigger run:

| Value to copy | Copy it from | Paste it into | When |
| --- | --- | --- | --- |
| Web Push **public VAPID key** | Firebase **Project settings > Cloud Messaging > Web configuration > Web Push certificates** | Cloud Build trigger **Substitution variables**: name `_FIREBASE_VAPID_KEY`, value = the copied public key | After generating the Web Push key pair; before the first trigger run |
| Fraud Defense **reCAPTCHA Enterprise site key** | Google Cloud **Fraud Defense > Keys**, after creating a score-based Web key | Paste the same key into Firebase **Security > App Check > Fraud Defense > reCAPTCHA Enterprise site key** and Cloud Build trigger **Substitution variables**: `_RECAPTCHA_ENTERPRISE_KEY` | After creating the key; before the first trigger run |
| OpenAI API key | [OpenAI API key page](https://platform.openai.com/api-keys) | Google Cloud **Secret Manager > Create secret**: name `OPENAI_API_KEY`, value = your OpenAI key | Before the first trigger run |

The VAPID **private** key never goes into GitHub or Cloud Build substitutions. The OpenAI key never goes into `web/.env`, GitHub, or substitutions. Firebase Web config, the VAPID public key, and the Fraud Defense site key are client configuration; Firebase describes its Web API key as [public by design](https://firebase.google.com/docs/projects/api-keys). Any older reCAPTCHA v3 **site key and secret key** you copied for the Classic option are not used in this Fraud Defense setup.

## 2. Prepare Firebase and copy the keys

1. Open [Firebase console](https://console.firebase.google.com/) and select **`reminder-app-a2150`**. In **Usage and billing**, upgrade to **Blaze** and attach your Google Cloud billing account if you have not already. Functions and scheduled dispatch require billing. In [Google Cloud Billing > Budgets & alerts](https://console.cloud.google.com/billing/), create a monthly $10 budget with alerts at $2 and $5. A budget alert is not a spending cap.
2. In Firebase **Build > Firestore Database**, create the **default** database if it does not exist. Choose **Native mode**, location **`us-south1` (Dallas)**, and **production mode**. If it already exists, check its location; do not create another database. Database location is difficult to change later.
3. In Firebase **Build > Authentication > Sign-in method**, open **Google**, switch it **on**, select a project support email, and **Save**. Then open Authentication **Settings > Authorized domains** and check that **`reminder-app-a2150.firebaseapp.com`** appears. Add it there if it is missing.
4. In Firebase **Project settings > Your apps**, confirm that the Web app with app ID **`1:831855773727:web:4c432059e91512daf5ad2a`** is listed. Its config is already in the repository; there is nothing to copy from this screen. If that app ID is absent, stop and check that you selected the correct Firebase project.
5. In Firebase **Project settings > Cloud Messaging > Web configuration > Web Push certificates**, click **Generate key pair** if none exists. Copy the **public key** shown there. Keep it available for the trigger field **`_FIREBASE_VAPID_KEY`** in section 3. Do not copy the private key. [Firebase's Web Push instructions](https://firebase.google.com/docs/cloud-messaging/web/get-started)
6. Open [Google Cloud Fraud Defense > Keys](https://console.cloud.google.com/security/recaptcha?project=reminder-app-a2150), check project **`reminder-app-a2150`**, and enable the reCAPTCHA Enterprise API if prompted. Click **Create key**. Set a display name such as **Remind PWA**, choose **Web** application, leave **Disable domain verification** off, and add domain **`reminder-app-a2150.firebaseapp.com`** without `https://`. Use the default **score-based** key; do not enable a checkbox challenge or testing-only score. Click **Create key** and copy its **site key**. [Google Cloud key creation](https://docs.cloud.google.com/recaptcha/docs/create-key-website)
7. Return to Firebase **Security > App Check > Apps > your Web app > Register**. Select **Fraud Defense (formerly reCAPTCHA Enterprise)**. Paste the key from step 6 into **reCAPTCHA Enterprise site key**. Leave **TTL = 1 hour** and **App risk = Medium (0.5)**, then save. Keep the same key for Cloud Build field **`_RECAPTCHA_ENTERPRISE_KEY`** in section 3. The app now uses Firebase's `ReCaptchaEnterpriseProvider`. Wait until the phone works before enabling additional Firestore enforcement. [Firebase Enterprise setup](https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider)
8. On the [OpenAI API key page](https://platform.openai.com/api-keys), create a regular project API key if you do not already have one; copy its value. Do not use an organization **Admin API key**. In [Google Cloud Secret Manager](https://console.cloud.google.com/security/secret-manager?project=reminder-app-a2150), select the same Google Cloud project, click **Create secret**, enter **`OPENAI_API_KEY`** as the name, paste the copied OpenAI key into the **secret value** field, and click **Create secret**. Confirm that the secret has an enabled version. Copy no value from Secret Manager into GitHub or the Cloud Build trigger. The functions' `defineSecret('OPENAI_API_KEY')` binding reads it at runtime. [OpenAI's API key setup](https://developers.openai.com/api/docs/quickstart); [Firebase secret parameters](https://firebase.google.com/docs/functions/config-env)

The app's normal URL will be **https://reminder-app-a2150.firebaseapp.com** after deployment, including for the first sign-in. It matches the configured `authDomain` and avoids Firefox's cross-origin redirect issue. The `.web.app` URL requires additional redirect-domain setup if you later choose to use it. There is no first-login UID setup. [Firebase redirect guidance](https://firebase.google.com/docs/auth/web/redirect-best-practices)

Firebase may prompt you to enable Cloud Functions, Cloud Build, Artifact Registry, Cloud Run, Cloud Scheduler, Eventarc, Firebase Rules, and Secret Manager APIs at first deployment. Enable them in this same project. The Cloud Scheduler job is created by the scheduled function; do not create a separate job manually.

## 3. Connect GitHub and enter the two public keys

1. In [Google Cloud console](https://console.cloud.google.com/?project=reminder-app-a2150), check the project selector at the top: it must say **`reminder-app-a2150`**. Signed in as the project owner, open the [Cloud Build API](https://console.cloud.google.com/apis/library/cloudbuild.googleapis.com?project=reminder-app-a2150) and the [Cloud Functions API](https://console.cloud.google.com/apis/library/cloudfunctions.googleapis.com?project=reminder-app-a2150); click **Enable** on either page that offers it. The build's service account can deploy functions but lacks `serviceusage.services.enable`, so a project owner must enable missing APIs. If a later deployment error names another disabled API, open its provided link as the project owner and enable it before rerunning. [Google Cloud API permissions](https://docs.cloud.google.com/service-usage/docs/enable-disable)
2. Open [IAM & Admin > Service Accounts](https://console.cloud.google.com/iam-admin/serviceaccounts?project=reminder-app-a2150). Click **Create service account**; name it **`remind-deployer`**. In its **Grant this service account access** step, add these project roles: **Firebase Admin**, **API Keys Viewer**, **Cloud Functions Admin**, **Service Account User**, and **Logs Writer**. Finish creation and note the service-account email shown in the list. Do not create or download a JSON key. Then return to [Secret Manager](https://console.cloud.google.com/security/secret-manager?project=reminder-app-a2150), select the checkbox beside **`OPENAI_API_KEY`**, open **Show Info Panel** if needed, click **Add Principal**, enter the `remind-deployer` email, select **Secret Manager > Secret Manager Viewer**, and save. Grant this role on that secret; it lets the build inspect secret metadata without reading its value. [Secret access controls](https://docs.cloud.google.com/secret-manager/docs/access-control); [grant access in the console](https://docs.cloud.google.com/secret-manager/docs/manage-access-to-secrets)
3. Open [Cloud Build > Triggers](https://console.cloud.google.com/cloud-build/triggers?project=reminder-app-a2150). Choose **Connect repository**, select the **Cloud Build GitHub App**, and authorize **`quintenBruce/Reminder-App`**. This is Google's build integration with GitHub, not the Codex GitHub plugin. Connect the repository to this Google Cloud project.
4. Click **Create trigger**. Use these exact settings:

   | Trigger field | Enter/select |
   | --- | --- |
   | Name | `remind-deploy` |
   | Event | **Push to a branch** |
   | Repository | `quintenBruce/Reminder-App` |
   | Branch pattern | `^master$` |
   | Configuration | **Cloud Build configuration file** |
   | Configuration file location | `cloudbuild.yaml` |
   | Service account | The `remind-deployer` account from step 2 |
   | Logs, if prompted | **Cloud Logging only** |

5. In that same trigger form, find **Substitution variables**. Add **two rows**; paste the *entire copied key string* as each value, without quotation marks or extra spaces:

   | Variable name | Paste this value |
   | --- | --- |
   | `_FIREBASE_VAPID_KEY` | Firebase Web Push **public** key copied in section 2, step 5 |
   | `_RECAPTCHA_ENTERPRISE_KEY` | Fraud Defense **reCAPTCHA Enterprise site** key copied in section 2, step 6 |

   Click **Create/Save** only after both rows are present. Do not put the old reCAPTCHA **secret** key or OpenAI key here. `_FUNCTIONS_REGION=us-south1` and the Firebase Web config are already defaults in `cloudbuild.yaml`; the project ID comes from Cloud Build's `$PROJECT_ID`. If the trigger form shows those existing defaults, leave them as they are. [Google Cloud trigger documentation](https://docs.cloud.google.com/build/docs/automating-builds/create-manage-triggers)

The build file runs tests, typechecks, and builds, then deploys Firebase Hosting, Firestore rules, and Functions. You do not need to copy build output into Firebase manually.

## 4. Deploy and sign in

1. The source is **already pushed** to GitHub `master`. Creating a trigger may not run it for an earlier push. In [Cloud Build > Triggers](https://console.cloud.google.com/cloud-build/triggers?project=reminder-app-a2150), find **`remind-deploy`**, select **Run** or **Run trigger**, choose **`master`** if asked, and start the first build. Open its build result and wait for both **verify-and-build** and **deploy** to succeed. If a step fails, read that step's error; after fixing the setting or permission, use **Run trigger** again. After this first successful run, future pushes to `master` start the deployment automatically.
2. On your Samsung phone or desktop Firefox, open [https://reminder-app-a2150.firebaseapp.com](https://reminder-app-a2150.firebaseapp.com) and use **Continue with Google**. Any verified Google account can sign up. Every account receives its own `users/{uid}` data in Firestore; account A cannot read or change account B's reminders or conversations through the app.
3. When switching accounts on one phone, use **Settings > Sign out**. The app unregisters that account's push token before signing out. Each account must use **Enable & test** after signing in to receive its own notifications. If sign-out cannot reach the server, retry it while online so the old account's push registration can be removed.

Open signup means others who know the URL can use the app and consume project resources. Callable functions require Google sign-in and App Check, with an app-wide limit of 30 transcription and 30 interpretation requests per UTC day. Set a Google Cloud budget alert and review usage; the alert is not a hard spending cap.

Fraud Defense includes 10,000 assessments per calendar month at no cost across the organization. Because this project has billing enabled, Google lists an $8 flat charge for assessments 10,001–100,000, then $0.001 per assessment above that. The 1-hour App Check TTL means the app refreshes around every 30 minutes while active. [Google Cloud billing](https://docs.cloud.google.com/recaptcha/docs/billing-information); [Firebase token refresh](https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider)

## 5. Phone validation

On the Samsung phone, use current Firefox for Android, open the `.firebaseapp.com` URL, then use Firefox's **Install** or **Add to Home screen** menu. In app **Settings**, choose **Enable & test** and allow notifications. Allow microphone access when prompted. Check a typed reminder, a spoken reminder, a voice edit, the confirmation readback and next dates, a five-minute repeat-until-Done reminder, Dismiss, Snooze, Done, and a completed item in History. Sign out and use a second Google account; verify that its reminders and conversation start empty, and that its test notification is registered separately. Check foreground, background, closed tab, phone restart, and temporary offline recovery. Record the actual phone/Android/Firefox versions while testing. Browser delivery is best effort; Samsung battery settings may delay background pushes.

If sign-in loops in Firefox, verify you opened `.firebaseapp.com`, not `.web.app`, and that Firebase Authentication lists that domain as authorized. If `Enable & test` fails, check browser notification permission, App Check registration, Web Push VAPID key, and the `registerDevice` function log. If Cloud Build fails, read the first failed step and its exact permission or validation error before changing roles or configuration.

If an older Cloud Build run reports **`Missing deploy settings: VITE_RECAPTCHA_SITE_KEY`**, it built a commit from before the Fraud Defense update. In the trigger, remove any obsolete `_RECAPTCHA_SITE_KEY` row, add `_RECAPTCHA_ENTERPRISE_KEY` with the Fraud Defense site key, then run the trigger on the latest `master` commit. The updated script checks for `VITE_RECAPTCHA_ENTERPRISE_KEY` instead.

If deployment reports **`Permissions denied enabling cloudfunctions.googleapis.com`**, the code and tests are past the build step; the deployer cannot turn on that Google Cloud API. As the project owner, open [Cloud Functions API for `reminder-app-a2150`](https://console.cloud.google.com/apis/library/cloudfunctions.googleapis.com?project=reminder-app-a2150), click **Enable**, wait for the page to show **Enabled**, then rerun `remind-deploy` on the latest `master`. If you cannot enable it yourself, check the signed-in Google account and ask a project owner or a user with **Service Usage Admin** to enable it. Do not grant broad API-enabling rights to `remind-deployer` just to pass this one setup step.

If deployment reports **`secretmanager.secrets.get` denied** for **`OPENAI_API_KEY`**, first check in [Secret Manager for `reminder-app-a2150`](https://console.cloud.google.com/security/secret-manager?project=reminder-app-a2150) that the exact secret name exists and has an enabled version. If absent, create it as described in section 2, step 8. If present, open [Cloud Build > Triggers](https://console.cloud.google.com/cloud-build/triggers?project=reminder-app-a2150), edit **`remind-deploy`**, and copy the email in its **Service account** field. Grant **Secret Manager Viewer** on the `OPENAI_API_KEY` secret to that exact email, using section 3, step 2. The trigger's selected service account controls the identity of triggered builds; `cloudbuild.yaml` does not select it. If the same 403 persists, open the **Troubleshooter URL in the error** and compare its denied principal with the trigger's service-account email and the secret's **Permissions** panel. The error concerns secret metadata; Viewer does not expose the OpenAI key value. Save any corrected grant, allow IAM changes to propagate, and rerun the trigger. The Firebase Extensions API warning in the same log is separate from this failure. [Cloud Build service accounts](https://docs.cloud.google.com/build/docs/securing-builds/configure-user-specified-service-accounts)

## Local verification and deployment files

The Cloud Build pipeline runs `pnpm install --frozen-lockfile`, `pnpm test`, `pnpm run typecheck:web`, `pnpm run build:functions`, and `pnpm run build:web`. The root pnpm lockfile pins local and Cloud Build dependencies; `functions/package-lock.json` pins the separate dependency install done by the Cloud Functions Node buildpack. `scripts/prepare-deploy.mjs` validates required settings and generates the ignored `functions/.env` file. Firestore rules permit each verified Google account to read only its own `users/{uid}` subtree; browser writes are denied. `firebase.json` has no build hook; always build before deploying manually.
